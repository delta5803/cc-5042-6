# 架构与算法说明

## 1. 数据流

```
要素（世界坐标） ── View 投影 ──▶ 屏幕锚点/区域环（CSS 像素）
                                      │
                    真实文字度量（measureText 包围盒 + 边距/光晕）
                                      │
                         固定顺序候选位置（12/9 个）
                                      │
              runLabeling：按确定顺序逐要素试探候选
                                      │
        ┌─────────────────────────────┴────────────────────────────┐
   已放置标签（矩形+字形度量+引线信息）                     隐藏要素（逐候选拒绝原因）
                                      │
                          renderer 全矢量绘制 + 调试层
```

每次视图变化（平移、缩放、旋转、DPR、视口尺寸）或要素编辑后，整条管线重新执行。

## 2. 真实文字边界

`CanvasTextMeasurer.measure` 优先使用 `TextMetrics.actualBoundingBoxLeft/Right/Ascent/Descent`
得到实际字形包围盒，再叠加显式内边距 `paddingX/paddingY` 与描边光晕 `halo`：

```
labelWidth  = actualLeft + actualRight + 2·paddingX + 2·halo
labelHeight = ascent + descent + 2·paddingY + 2·halo
```

不同文字体系（拉丁比例宽度、CJK/谚文/假名全角、阿拉伯文 shaping、希腊/西里尔字母）
与同体系字符（`W` 与 `i`）的宽度差异全部来自字体度量结果。
测试中的 `FakeTextMeasurer` 以 code point 区间逐字累加模拟该差异，接口与生产度量器完全一致。

## 3. 确定性选择顺序

要素比较器（无随机、无时间依赖）：

1. 优先级 `priority` 降序；
2. 同优先级点要素先于区域要素；
3. 再按 id 做数值/字典序兜底。

每个要素的候选位置也是固定数组（点 12 个、区域 9 个，见 `candidate.js`），
因此同一输入的任何一次布局结果逐字节一致；轻微平移时要素与候选顺序不变，
已可见标签尽量保持原候选位置（有专门的稳定性测试，阈值 80%）。

## 4. 屏幕碰撞 ≠ 世界距离

- 碰撞判定只在屏幕 CSS 像素空间进行：标签矩形之间做带 `collisionPadding` 的 AABB 相交，
  标签与其他要素的点标记障碍盒做 AABB 相交。
- 世界空间距离不参与碰撞。旋转是保距变换，但标签保持屏幕横排，锚点排布方向相对标签
  方向改变后，地理上相距很远的要素也可能在屏幕上重叠——测试中构造了世界距离
  约 2.8 倍标签高度、屏幕矩形真实相交的碰撞对作为证据。
- 区域要素的居中候选要求标签中心位于（屏幕空间的）区域环内；外移候选允许出界并绘制引线。

## 5. 拒绝原因

每个候选独立记录原因集合，主原因按固定优先级取：
`off-canvas > label-collision > marker-collision > outside-region`。

- `off-canvas`：矩形超出视口与 `edgeMargin`；
- `label-collision`：与已放置标签相交；
- `marker-collision`：与其他点标记障碍盒相交；
- `outside-region`：区域居中候选的中心不在区域环内。

高密度场景下引擎会尝试全部候选再决定隐藏，而不是直接丢弃低优先项；
界面结果表与画布调试层展示的原因均来自该实际运算。

## 6. DPR 与像素密度

布局坐标始终是 CSS 像素。`renderer.configureCanvas` 仅把画布后备存储放大 `dpr` 倍并设置
`setTransform(dpr,…)`，因此 DPR 变化时标签的 CSS 像素矩形完全一致（有测试断言），
只是光栅化密度改变。

## 7. 渲染

所有底图网格、区域面、点标记、引线、标签文字（含白色光晕）都直接绘制在同一个 Canvas 上，
不创建任何 HTML 文字标签。调试模式额外绘制候选矩形、隐藏叉号与区域最大内切锚点。

## 8. 碰撞候选加速（空间索引）

原始实现中，每个候选矩形都要与“全部已放置标签”和“全部点标记障碍”逐一做精确 AABB，
密集场景是 O(候选数 × 已放置数) 的全量两两比较。现在改为宽相位 + 精确测试两段式，
实现在 `src/spatial-index.js`（`RectSpatialIndex`，均匀哈希网格）：

```
候选矩形（按 collisionPadding 膨胀） ──网格 query──▶ 可能相邻的少量条目
                                                        │
                                    rectsIntersect 精确 AABB 判定（仍是唯一判定依据）
```

**为什么不改变结果**：宽相位只负责把“必然不相交”的条目排除，返回的一定是真实相交的
超集；最终是否碰撞仍由同一个 `rectsIntersect` 决定。要素处理顺序、候选顺序、拒绝原因
优先级、稳定性规则全部原样保留。

**计算顺序**（可解释的成本分解）：

1. 逐要素（优先级降序 → 点先区域 → id）取候选，顺序与加速前一致；
2. 对每个候选，用其膨胀后的矩形查询网格，得到候选条目集合；
3. 只对该集合逐条 `rectsIntersect`，命中即记 `label-collision` / `marker-collision`；
4. 放置成功后把该标签矩形插入索引，供后续要素查询。

**不因可见区裁剪漏检**：索引键是任意整数单元坐标（Map），入索引时不按视口过滤。
画布外或跨边缘的矩形照常入索引并参与精确判定——`off-canvas` 仍由 `withinCanvas`
独立判定，越界标签不会因为“不在可见区”被静默跳过。索引每帧随重映射后的矩形重建，
平移/缩放/旋转/DPR/改视口后不存在跨帧陈旧条目。单个矩形横跨单元过多时进入 `oversized`
列表、查询时始终参与精确测试，避免极端坐标下的爆炸并保持正确性。

**保留运行参照**：`runLabeling` 支持 `collisionStrategy: 'brute-force'`，走改动前逐条
全量比较的旧路径。它用于等价性门禁（`npm run bench:check`）与界面切换对照
（“碰撞候选加速”下拉框），任何行为差异都以失败暴露。

**成本分解**：`runLabeling` 返回值新增 `cost`：

| 字段 | 含义 |
| --- | --- |
| `candidates` | 试探的候选总数 |
| `exactTests` | 实际执行的精确 AABB 相交测试次数（加速的核心指标） |
| `broadPhaseHits` | 宽相位返回的候选条目数（暴力策略下为 0） |
| `labelCollisions` / `markerCollisions` | 标签/标记碰撞计数 |
| `offCanvasCandidates` / `outsideRegionCandidates` | 越界/区域外候选计数 |
| `layoutMs` | 本帧布局内循环耗时 |

界面“布局成本分解（本帧）”面板与 CLI `report` 的“策略 …”行都直接展示以上数值。
成本计数只统计真实执行，不使用任何默认值填空。

## 9. 基准

`npm run bench` 在“密集标签 + 慢速平移”负载下对比两种策略：每个场景先校验最终采用集
逐字节一致，再交替取样计时并输出中位/均值、精确测试减少比例与碰撞数。所有参数
（要素规模、间距、平移步长、视图尺寸、样本数）都显式给定并打印，不以默认值遮掩差异。
`npm run bench:check` 只做正确性门禁，不做计时。
